# PhotoLab — React + JavaScript

Чёрно-синий фронтенд для Go Photo Editor. React + Vite, без Canvas и TypeScript.

## Запуск

Из корня `photo_editor`:

```bash
docker compose up -d --build
```

В другом терминале:

```bash
cd frontend
npm install
npm run dev
```

Открой <http://localhost:5173>.

## Как работает

1. В кнопке «Войти» зарегистрируйся или войди. `POST /register` и `POST /login` выполняются по-настоящему.
2. Загрузи PNG и выбери один из фильтров: Negative, Blur, Sharpen, FlipX.
3. Для Blur и Sharpen настрой sigma.
4. Нажми **«Применить фильтр»** вверху панели «Инструменты». Файл станет Base64, фронтенд отправит `POST /task`.
5. Фронтенд проверяет `GET /status/{id}`, дожидается `ready`, получает настоящий PNG через `GET /result/{id}` с Bearer-токеном и показывает его.
6. Нажми **«Скачать результат PNG»** под фотографией.

До обработки показывается CSS-предпросмотр. Для Blur радиус размытия автоматически пересчитывается из исходных пикселей в экранные с учётом размера изображения: это близкая оценка, а не пиксельно идентичный эффект. После успешной обработки показывается **реальный PNG от Go ImageProcessor**. Сравнение «до/после» работает с обоими.

## Маршрутизация

`vite.config.js` перенаправляет `/api/*` в `http://127.0.0.1:8001/*`. Благодаря proxy браузер отправляет запросы на `localhost:5173`, и не нужно менять CORS или маршруты Go.

| Фронтенд вызывает | Go-сервер получает |
| --- | --- |
| `/api/register` | `POST /register` |
| `/api/login` | `POST /login` |
| `/api/task` | `POST /task` |
| `/api/status/{id}` | `GET /status/{id}` |
| `/api/result/{id}` | `GET /result/{id}` |

При запуске production-сборки `npm run build` потребуется аналогичный reverse proxy для `/api`; Vite dev proxy работает **только во время разработки**.

## Данные и ограничения

- Токен сессии хранится в `sessionStorage` браузера. После перезапуска Go-сервера нужно войти повторно, потому что сессии на сервере хранятся в RAM.
- Загруженные изображения и результаты хранятся только в текущей вкладке (в памяти), на диск сами не сохраняются.
- Клиент ограничивает размер исходного PNG 70 МиБ. Base64 добавляет около 33% размера. Если в Go остался `MaxTaskMessageSize = 49 * 1024 * 1024`, большие файлы получат HTTP 413: согласуй лимит в Go и RabbitMQ.
- В интерфейсе есть только PNG, так как Go Consumer использует `png.Decode`.
- На данном этапе одновременно запускается одна серверная обработка из вкладки; при переключении между изображениями результат сохраняется для исходной фотографии.
- История — локальная, не серверная. Статус `failed` показывает ошибку, `in_progress` продолжает опрашиваться.

## Исправления отображения

- Кнопка обработки расположена вверху панели инструментов и видна без прокрутки.
- PNG всегда вписывается целиком в область редактора при масштабе 100% (режим `object-fit: contain`).
- При масштабе выше 100% изображение может обрезаться намеренно — это приближение.
- Рабочая область прокручивается вертикально независимо от боковой панели.

## Интерфейс

В интерфейсе нет технических сообщений о Go, RabbitMQ, API и портах. Успешные операции не вызывают всплывающие уведомления; ошибки показываются компактно в рабочей области.
